# 《哈基米塔防》PRD v0.3

> 原创萌宠塔防网页游戏。本文档是开发与代码审核的唯一需求基准。

## 1. 概述

| 项 | 内容 |
|---|---|
| 游戏名 | 《哈基米塔防》（原创 IP，不使用任何现有游戏的素材、名称、数值） |
| 类型 | 萌宠主题经典路径塔防 + 宠物收集养成（纯放置挂机，无手动技能） |
| 平台 | 浏览器网页（Vue 3 + Vite + TypeScript），手机竖屏 / 电脑宽屏自适应 |
| 主题 | 哈基米（猫猫）和狗勾军团保卫粮仓，拦截偷粮的鼠贼军团 |
| 存档 | localStorage 本地存档（带版本迁移、导出导入） |
| 音效 | 无 |
| 付费/联网 | 无 |

## 2. 明确不做（非目标）

- 不复刻任何现有游戏的美术、名称、数值
- 无音效、无内购、无联网功能、无体力系统
- 无战斗内手动技能（操作仅限：排兵布阵、放塔、升级、出售、加速开关、提前召唤）

## 3. 核心循环

```
出战关卡 → 自动战斗掉小鱼干🐟(战斗内货币) → 通关得猫薄荷🌿(抽蛋货币)
     ↑                                      ↓
宠物升星变强 ← 重复宠物转碎片 ← 孵蛋获得新猫狗(或重复)
```

## 4. 战斗系统

- **地图**：网格制。敌人沿固定路径（路点序列）从鼠洞走向粮仓；路径旁分布建造格。
- **玩家操作全集**：
  1. 战前编队：从收藏中选 ≤6 只出战
  2. 点空建造格 → 从编队选宠物放置（消耗小鱼干）
  3. 点已放宠物 → 升级（Lv1→Lv3）或出售（返还已投入的 60%）
  4. 1x / 2x 加速开关
  5. 提前召唤下一波：波间倒计时时立即开始下一波，并预支该波清空奖励的 50%
- **胜负**：撑过全部波次=胜利；敌人到达粮仓扣粮仓血量（普通敌人 1 点，Boss 5 点），归零=失败。失败无资源惩罚。
- **星级**：通关=1★；通关且血量>60%=2★；通关且满血=3★。取历史最高星。
- **波次**：每关 5~8 波；首波 15 秒准备，其后波间倒计时 10 秒；末波含 Boss。

- **战斗内等级**（单局）：Lv1~3，Lv2/Lv3 显著提升攻击与射程。

## 7. 孵蛋抽卡

| 方式 | 消耗 | 规则 |
|---|---|---|
| 单抽 | 100🌿 | — |
| 十连 | 900🌿 | 必出 ≥1 只 R+ |

概率：N 55% · R 30% · SR 12% · SSR 3%。

保底（"最多 N 抽内必出"语义）：
- 连续 20 抽未出 SR+ → 第 20 抽必出 SR+（出 SR+ 后重新计数）
- 连续 40 抽未出 SSR → 第 40 抽必出 SSR（双计数器清零）
- 首次十连必出 SR+（新手保底）

货币产出：首通每关 ~300🌿（第 8 关 500）；星数里程碑 6/12/18/24★ 各一档大额奖励；重复通关给首通的 20%。战役期总产出约 7100🌿 ≈ 71~79 抽，通关期期望集齐 ~18-19/21 只（N+R 全员 + 大部分 SR）；全图鉴期望约 120 抽，属长线收集目标；SSR 双子 5★ 需约 4 次重复，为毕业级目标。

## 11. 存档设计

- localStorage key：`hachimi-td:save:v1`，JSON 带版本号
- 写入时机：关卡结算 / 抽卡 / 升星 / 编队变更后立即写；**战斗中不写档**（中途退出=放弃本局）
- 损坏档：备份到 `hachimi-td:backup:corrupted` 后开新档并提示
- 版本迁移：migrate 函数链 v1→v2→…，缺字段填默认值
- localStorage 不可用（如无痕模式）：提示"进度无法保存"，内存档继续游戏
- 导出：生成文本可复制；导入：解析校验合法才覆盖

存档 schema：
```jsonc
{
  "version": 1,
  "currencies": { "catnip": 0 },
  "pets": [ { "id": "tianyuan-cat", "stars": 1, "shards": 0 } ],
  "lineup": ["tianyuan-cat", "tianyuan-dog"],
  "levels": { "1": { "stars": 3, "cleared": true } },
  "endless": { "bestWave": 0, "claimedMilestones": [] },
  "gacha": { "totalDraws": 0, "srPity": 0, "ssrPity": 0, "firstTenDone": false },
  "starMilestones": [],
  "stats": { "totalKills": 0, "battlesWon": 0 }
}
```

## 12. 架构要求（硬性）

1. **战斗引擎零渲染依赖**：引擎只产出实体状态，不 import 渲染/Vue 代码；渲染从引擎快照读取。
2. **素材可替换**：所有视觉（宠物/敌人/弹道/地块/UI 图标）经 `src/render/` 的接口 + 注册表访问；v1 用 `providers/emoji.ts` 占位实现；未来矢量/图片素材只需新增 provider 实现同一接口。
3. 游戏数值全部收敛在 `src/game/data/` 数据表，禁止散落硬编码。
4. 引擎为纯 TS 类，时间推进用固定逻辑步长；可被 Vitest 直接驱动测试。

## 13. 质量要求（硬性）

1. Vitest 单测覆盖：寻路、索敌、伤害/护甲/减速、波次推进、经济结算、抽卡概率与保底、升星、存档迁移与容错、组件关键交互。
2. `pnpm test` 全绿、`vue-tsc -b` 零错误、`vite build` 成功，三者作为每里程碑完成标准。
3. 每个模块完成后由多个 subagent 从多维度（逻辑正确性、边界条件、类型安全、数值平衡、Vue 规范）审核，问题修复后进入下一里程碑。
4. 最终交付：可运行工程 + README（含运行方式）+ 构建产物。
